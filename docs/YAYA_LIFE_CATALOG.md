# 芽芽的表情、生活动作与自主活动

这份表同时服务于产品设计和其他 agent：先判断芽芽为什么做一件事，再选外显表情、身体动作和道具。当前有 31 个可调用的表情状态、19 个主动作，以及 3 个兼容交互动作。代码清单在 `src/yaya-catalog.js`；行为调度在 `src/yaya-life.js`，具体绘制仍由原角色、骨架和场景模块负责。

## 1. 内部需求与外显表情分开

“饿了”是需求，“期待吃饭”是表情，“坐在桌旁吃饭”是动作。三者不能共用一个状态变量。相同需求可以有不同表情：轻微口渴可以很平静，运动后口渴可以先疲惫；不同需求也可以使用同一种表情，例如期待新玩具和期待午饭。

建议保留以下层次：

| 层次 | 回答的问题 | 芽芽中的例子 |
| --- | --- | --- |
| 身体与参与需求 | 现在缺什么？ | hunger、thirst、fatigue、boredom |
| 当前意图 | 接下来想做什么？ | 找饭吃、喝水、休息、找个玩具 |
| 表情与姿态 | 观众怎么看懂它？ | hopeful、sleepy、curious、relieved |
| 动作与场景 | 它具体怎么做？ | 餐桌旁吃饭、床上仰卧睡觉、拿球玩 |
| 结果 | 这件事改变了什么？ | 饥饿降低、口渴降低、精力恢复、兴趣提高 |

`yaya-life.js` 实际保存的需求字段是 `hunger`（饥饿）、`thirst`（口渴）、`fatigue`（疲惫）和 `boredom`（无聊），取值 0–100；越高越需要照料或活动。页面以 `100 - 值` 显示“饱足、水分、精力、兴致”。因此精力恢复对应 `fatigue` 下降，兴致提高对应 `boredom` 下降。不要向调度器传入 `energy` 或 `interest`，它们只是设计讨论中的正向语义名。

31 个外显状态足够覆盖目前的主要表达。不要为了扩充数量，再加几个难以区分的“开心 2”“困倦 2”。生活感优先来自动机、动作过程、停顿和结果。

## 2. 表情分类及区别

下面 7 组完整覆盖现有 31 个 key，每个只归入一组。`domain` 进一步区分 emotion、cognition、social、body、engagement，避免把困倦、睡着和无聊都计入“负面情绪”。

| 分类 | key | 显示名 | 首要识别线索 |
| --- | --- | --- | --- |
| 平静与愉快 | idle | 平静 | 正常眼、小微笑、呼吸，圆手保持两侧 |
| 平静与愉快 | happy | 开心 | 弯眼微笑、轻轻弹一下 |
| 平静与愉快 | excited | 兴奋 | 睁大眼张嘴笑、身体上提，短时高能量 |
| 平静与愉快 | laugh | 咯咯笑 | 月牙眼、单手近嘴、小幅轻抖两下 |
| 平静与愉快 | proud | 自豪 | 抬头挺胸、自信小笑，完成事情后出现 |
| 平静与愉快 | relieved | 安心 | 呼气、闭眼舒展、叶子放松落回 |

| 社交与偏好 | love | 喜欢 | 爱心眼、胸前小拳、明显亲近 |
| 社交与偏好 | shy | 害羞 | 手遮一点眼睛、仍偷偷看、腮红 |
| 社交与偏好 | suspicious | 悄悄观察 | 侧着看、手靠额侧、小幅动作 |
| 社交与偏好 | disgusted | 不喜欢 | 摇头、小幅推开、交叉叶子；表示边界 |

| 社交与偏好 | starstruck | 闪闪着迷 | 发光眼、目光停在喜爱对象上 |
| 玩耍态度 | playful | 调皮 | 友好眨眼、吐舌、邀请玩耍 |
| 玩耍态度 | mischief | 小淘气 | 点脸颊、眨眼吐舌、轻微玩笑后的神态 |
| 身体状态 | sleepy | 困倦 | 眼皮重、动作慢、叶子垂；随后去休息 |
| 身体状态 | dizzy | 晕乎乎 | 旋涡眼、星星，站稳后很快恢复 |
| 身体状态 | ko | 睡着啦 | 入睡的面部状态；完整睡姿调用 sleep |
| 参与需求 | bored | 有点无聊 | 平嘴、慢环顾，随后自己找事情做 |

这些分类是产品语义，不是临床心理量表。底层保留原 key 便于兼容；显示名可以更清楚，例如将 `scared` 从“小紧张”区分为“有点害怕”。`playful` 和 `mischief` 的脸型仍然接近，需要靠事件上下文区分，不宜连续放进随机演示来冒充两种鲜明情绪。

## 3. 查缺补漏：先组合，再新增

| 缺口 | 当前解决方式 | 表现要点 | 是否新增脸型 |
| --- | --- | --- | --- |
| 饿了 | hunger 驱动 hopeful → eat → relieved | 看向饭碗，坐在桌旁吃，吃后放松 | 否 |
| 口渴 | thirst 驱动 drink → relieved | 杯子真的贴嘴，喝完放下 | 否 |
| 疲惫 | fatigue 上升驱动 sleepy → sleep | 先放慢，再去睡，避免瞬间切成“昏迷” | 否 |
| 无聊 | boredom 上升驱动 curious → walk/ball | 无聊短暂，主动找事做 | 已有 bored |
| 满足 | happy/relieved → idle | 慢一点、停一停、呼气；不要每次都庆祝 | 否 |
| 想陪伴 | 未来用 love → wave/hug | 看向伙伴、抱玩偶，再能自行安静玩 | 计划；不加惩罚性的孤独值 |

不扩充持续哭泣、过度愤怒、受伤或绝望状态作为“随机日常”。保留现有不适表达供明确事件调用，再接安抚或恢复。生命感不依赖不断出现负面状态。

## 4. 已实现动作表

以下是旧播放器的基础 `actions`，`implemented: true` 表示该 key 已有可用基础绘制与动作。它不代表完整房间行为。桌旁吃饭仍未加入走到餐桌、入座的空间过渡；卧室则已通过单独的 `roomBehaviors` 实现上床、仰卧、盖被、起床和离床，见后文与 [YAYA_BEDROOM.md](YAYA_BEDROOM.md)。

| run | 小跑 | 漫画跑动线 | 前倾 → 快步腾空 → 往返 → 站稳 | 精力足、玩耍 |

| jump | 跳高 | 无 | 蓄力 → 起跳 → 腾空 → 落地缓冲 | 玩耍 |
| walk | 走一走 | 地面与脚部接触 | 看方向 → 慢步 → 踏步转身 → 走回来 | 探索、待久了 |
| sway | 摇摆 | 无 | 左摆 → 右摆 → 回中间 | 等待、跟节奏 |
| spin | 踏步转圈 | 地面与脚部接触 | 换重心 → 交替迈步 → 转一圈 → 站稳 | 短暂自娱 |
| stomp | 跺跺脚 | 无 | 抬脚 → 有节奏落地 → 停稳 | 模仿节奏、明确指令 |

另保留 3 个兼容 key：`hello` 是回应招呼，`cuddle` 是被摸摸后的反应，`play` 是原主舞台互动玩球。它们有实现，但不重复占据 19 项主动作表。新的自主行为优先使用 `wave`、`hug`、`ball` 这些更具体的动作。

`props` 既列可握持物品，也列支撑动作的场景物和漫画线索。它是设计清单，不是资产文件地址。真实道具必须交给场景或角色绘制，不能只加一个图标便宣称宠物在做这件事。

### 连续卧室行为

`YayaCatalog.roomBehaviors` 和 `getRoomBehavior(key)` 描述以下 7 项。通过卧室页面的 `yayaBedroom.request(key)` 调用；它们不是旧播放器的片段名称，没有固定四秒循环时长。

| 命令 | 道具与场景 | 连续过程 |
| --- | --- | --- |
| window | 窗户、空地 | 沿空地走近窗户 → 转向观察 → 回地毯 |
| read | 矮柜、绘本、地毯 | 走近取书 → 带到地毯 → 坐下翻看 → 合书 → 走回放稳 → 收手 |
| teddy | 矮柜、泰迪熊、地毯 | 接触后抱起 → 带到地毯 → 轻抱轻靠 → 回柜子放好 |
| tidy | 已归位的小熊与绘本 | 走近柜子检查 → 看看整理结果 → 返回 |
| lamp | 床头灯与拉绳 | 走到灯旁 → 短手碰到拉绳 → 灯光变化 → 收手离开 |
| sleep | 低床、枕头、被子 | 关灯 → 上床坐稳 → 仰卧 → 真手拉被 → 小睡 → 推被 → 起身下床 |
| wander | 地毯与过道 | 看方向 → 迈步转向 → 走一小圈 → 停下歇歇 |

自动选择会执行完整过程、留出安静时间并避开短期重复；灯和检查柜子只接受手动调用。物品尚未放好、手尚未收回、身体仍在床上时，新的请求排队等待安全交接。卧室目前按行为冷却时间选择日常活动，尚未连接下面花园模型的饥饿、口渴等需求数值。

## 6. 空闲时有目的地生活

每段自主行为遵循“意图 → 执行 → 反馈 → 静息”。这里的意图不是一段说明文字：好奇要朝目标看，期待要看食物或玩具，做完之后需求数值和外显节奏都应变化。

| 行为段 | 可执行序列 | 结果 |
| --- | --- | --- |
| 看看旁边 | curious → turn → idle | 短暂观察，回到陪伴 |
| 出去探索 | curious → walk → relieved | 增加新鲜感，轻微消耗精力 |
| 找球玩 | hopeful → ball → happy | 兴趣恢复，少量消耗精力 |
| 自己跳舞 | happy → dance → relieved | 玩过后放松 |
| 抱抱玩偶 | love → hug → relieved | 安静的自我安慰和玩耍 |
| 活动一下 | stretch → run → drink → relieved | 先舒展，跑完喝水，再放松 |
| 吃一顿饭 | hopeful → eat → drink → relieved | 饥饿和口渴降低 |
| 喝点水 | drink → relieved | 口渴降低 |
| 打个盹 | sleepy → sleep → stretch → relieved | 精力恢复；演示可用约 24 秒睡眠 |

调度约束：

- 先处理较高的身体需求，再选择探索或玩耍。无聊不等于低精力，不能总用睡觉解决。
- 做完一段再选下一段，中间留呼吸、眨眼和四处看看。不能每一秒换表情，也不能把随机动作排成不停的表演。
- 给最近做过的行为设冷却和重复惩罚，不连续吃饭、不反复庆祝，也不连续转圈直到眩晕。
- 用户点选和照料优先：停止或挂起当前自主序列，执行用户动作；恢复时给一小段安静时间。
- 页面在后台时暂停调度和需求时钟，回到页面后从可理解的状态继续，不补播离开期间的一长串动作。
- 显式暂停应停止自主变化。演示速度与未来真实作息分开：24 秒睡眠是预览节奏，不是真实宠物一天的睡眠模型。
- 需求只在动作实际完成后给予反馈，避免被中途打断的吃饭仍然瞬间满饱。

## 7. 比动作数量更重要的绘制约束

胳膊根部仍固定在腮红高度，圆手属于同一只真实手。除挥手、伸手、伸懒腰等明确需要伸展的动作，手臂不应明显变长。转圈时保持日常的短小圆手比例，只微微放低或摆动，不把“自然下垂”画成长长的手臂。

吃饭时角色坐在桌子后面，椅子支撑身体；桌面与碗有接触，勺柄被真实圆手握住。碗、桌子和椅子属于世界场景，不能跟着手漂移。喝水时杯子由手掌握点驱动，杯口在喝水阶段靠近嘴；不要另外画一套线条胳膊代替现有骨架。

转身时脸、眼睛、嘴属于同一个头部坐标，使用同一转角；叶子可以有柔软跟随。脚先着地换重心，再让身体转，不在脚下滑动。睡觉时后脑落在枕头上、身体仰卧、脸朝上，侧脸露在被子外；手和身体主要部分在被子里。

## 8. 给其他 agent 的数据使用方法

浏览器加载 `yaya-catalog.js` 后读取 `globalThis.YayaCatalog`；Node CommonJS 或 VM 也可读取，无浏览器或绘图库依赖。顶层和嵌套数据均冻结，消费者不要就地修改它。

```js
const C = globalThis.YayaCatalog;
const menu = C.actions.filter(item => item.implemented && item.inMenu);
const possibleIdleActions = C.actions.filter(item => item.implemented && item.autonomous);
const eating = C.getAction('eat');
// eating.props / eating.beats / eating.trigger 供 UI 和语义决策使用。
// 真正调用前仍应检查自己的 renderer 是否支持目标 key。
```

`autonomous: true` 只是适合自主调用，不等于已经被调度器启用；调度器应采用经过设计的行为段。`duration` 是现有基础动画的循环时长，允许睡眠等行为播放多个循环；未实现项为 `null`。`gaps` 中的 hunger、thirst、energy、interest 等是语义缺口或需求，不是新绘制 key，不能传给角色并期待新脸型。其中语义项 `energy` 对应实际需求字段 `fatigue`，`interest` 对应 `boredom`，增减方向相反；直接读取运行状态应使用 `yayaLife.getState().needs` 的四个真实字段。

新增动作时同步检查：角色实现、手臂求解、道具接触、前侧后遮挡、catalog 状态、主页面展示、行为触发与退出。只有这些能闭合，才能把 `implemented` 从 `false` 改为 `true`。

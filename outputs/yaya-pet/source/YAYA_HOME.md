# 芽芽的家：布局、家具与行为约定

这一版把房间当成一个可以持续生活的空间。总平面先明确房间之间的关系，再布置靠墙的家具和中间的活动通道，最后根据真实家具决定芽芽能做什么。不能先有一段动作，再把任意道具贴到手边。

## 六个空间，两套独立卧室

用户确认第二个卫生间也属于第二间卧室，因此这里采用“两间卧室，各带独卫；一个公共客厅；一个餐厨一体空间”。没有公卫，也没有从客厅直通卫生间的门。

| 空间 | 可直接到达 | 用途与归属 |
| --- | --- | --- |
| 芽芽卧室 | 客厅、芽芽独卫 | 芽芽自己的床、书桌、衣柜、绘本与小熊 |
| 芽芽独卫 | 芽芽卧室 | 洗手台、镜子、毛巾、坐便器、淋浴区 |
| 客厅 | 两间卧室、餐厨 | 连接房间，公共休息和玩耍 |
| 餐厨一体 | 客厅 | 沿墙操作台，中间餐桌和成组餐椅 |
| 伙伴卧室 | 客厅、伙伴独卫 | 为未来另一只宠物保留，不虚构已有住客 |
| 伙伴独卫 | 伙伴卧室 | 第二套完整独立卫浴 |

总平面用 `plan` 矩形描述相邻关系，五个 `connections` 都位于两个真实相邻矩形的公共边上。每条连接有两个互相指向的门，不能只在一边画一扇没有目的地的门。房间内使用统一的十乘八设计单位，方便对齐角色尺度；总平面是功能与相邻关系示意，不是建筑施工尺寸图。

## 相机与摆放

房间从斜上方观察，地面有两个可辨认的方向。`x0` 与 `z0` 是两面可见的墙，靠近观众的两边打开。右侧的门画在 `z0` 墙面，并在墙体中留出实际门洞。门的位置、走到门前的位置与房间切换共用同一份数据。

卧室的床头贴住 `x0` 墙，床沿沿 `+x` 延伸。枕头靠床头，被子覆盖床垫，床尾前方留空。低柜、衣柜和床头柜也贴同一面墙；书桌靠 `z0` 墙，在两扇门之间。椅子放在桌前，芽芽需先到椅子旁，不能坐在空气里。窗户、空调、画与顶灯属于墙面或顶部设施，不占地面通道。

客厅沙发靠墙，茶几在沙发前方，门口之间保留连续通道。餐厨里的冰箱、水槽、备餐台、灶台沿一面墙布置；餐桌位于厨房操作区之外，两把椅子分居桌的两边。卫生间将洗手、淋浴和坐便区域分开，门前及中央留空。

角色仍是原有的芽芽。房间不能通过把角色缩成完全不同的比例来容纳家具：门洞需要容纳转向门口后的身体宽度，椅面容得下圆身体，物品高度与短手可达范围相符。普通胳膊长度和固定肩根不因房间变大而改变。

## 数据契约

`src/yaya-home-layout.js` 导出 `globalThis.YayaHomeLayout`，不依赖画布或浏览器 DOM。

```js
const room = YayaHomeLayout.getRoom('bedroom');
const bed = YayaHomeLayout.getFurniture(room, 'bed');
const path = YayaHomeLayout.roomPath('bedroom', 'bathroom');
// ['bedroom', 'living', 'guestroom', 'bathroom']
const door = room.doors.find(item => item.to === 'living');
const approach = YayaHomeLayout.doorPoint(room, door, 1.0);
```

家具格式为 `{ id, kind, x, z, w, d, h, ... }`：`x,z` 是地面占地矩形的起点，不是中心；`w,d` 为两条地面边的长度；`h` 为家具自身高度。墙上设施另有 `elevation` 表示离地高度。`mounted:true` 和 `blocks:false` 的顶灯、窗户、空调、地毯等不阻碍寻路。床头灯通过 `parent:'bedside'` 和柜面的高度获得支撑，不能将其另算一件地面障碍物。

门格式为 `{ id, wall, offset, width, to, toDoor, label }`。**`offset` 是门洞中心，不是左边缘。** `doorPoint` 从门中心向房内偏移，提供进出门的落脚位置。每个 `toDoor` 都能在目标房间找到反向连接。

`room.items` 保存属于家具表面的绘本、小熊；`room.points` 保存家具前方可站立的接近点；床另有 `pillow`、`sit`、`sleep` 等接触参照。渲染器、动作控制器和热点应读取这份共同的数据，避免图里有柜子、寻路却从柜子中间穿过去。

## 行为的完整过程

| 目标 | 需要的过程 | 不能省略的关系 |
| --- | --- | --- |
| 去另一个房间 | 绕开家具 → 走到对应门前 → 通过门洞 → 从目标房间配对的门进入 | 不直接在房间中央换背景或瞬移 |
| 在床上睡觉 | 到床边 → 坐上床沿 → 躺下 → 后脑靠枕头 → 被子盖住身体 → 入睡 | 床头、枕头、身体与被子使用同一组世界坐标 |
| 起床 | 睁眼 → 掀被 → 坐起 → 下床 → 双脚落地 → 离开床边 | 不能在睡姿时直接开始地面行走 |
| 看书 | 到低柜 → 接触书 → 拿走 → 到可坐的位置 → 阅读翻页 → 合书 → 归还 | 一本书只属于柜子或手中的一方 |
| 吃饭 | 到餐桌椅旁 → 坐稳 → 手接近桌上餐具 → 送到嘴边 → 放回 → 离席 | 桌、椅、碗、手的位置一致 |
| 洗手 | 到洗手台 → 近侧手接水 → 关水、收手 → 略转向观众，在胸前搓手 → 转回盆前冲洗 → 关水、放手、离开 | 接水在身体侧面；搓手在胸前，均保持短手可达 |
| 安静活动 | 观察目标 → 走近 → 停稳 → 小幅动作 → 停顿 | 不每隔几秒强迫切换高能量表演 |

这张表区分设计约定与实现状态：有家具、有活动名字，不等于完整交互已经实现。新增行为时应在控制器中补全准备、接触、保持和收尾，再在界面标记可用。伙伴卧室虽然可以参观，仍保留未来住客的归属；不要自动安排芽芽占用伙伴的床或独立生活用品。

## 连续性和遮挡

所有角色运动仍使用原身体和手臂求解器。肩根在腮红高度固定，圆手保持正常大小，日常胳膊不因侧身、转向或休息而变长。转身时眼睛随身体一起改变朝向，不给五官单独加惯性。叶子可以柔软跟随。

家具与角色按地面深度排列。桌面应挡住桌后的身体，手在拿取时出现在道具正确的一侧；墙上的空调不应被当成地面柜子；床上的角色需要被床垫支撑，再由被子覆盖。任何“坐着”状态都应对应具体座面高度，不能只把腿藏掉。

道具的拿起与放下使用同一物体的所属状态。手先接触，道具才开始跟手；归还时先接触柜面，再松手。短手够不到时，让角色移动或调整姿势，不延长胳膊来掩盖空间安排问题。

### 餐桌与水龙头：先算接触，再画动作

坐姿把身体根节点抬到座面后，手也随之抬高。因此桌高不能凭站姿或外观随意指定。本版选择餐桌远侧的低椅：座面 `(5.89, 3.60, .40)`，桌高 `1.35`，角色朝向桌面 `yaw=-1.087827`。碗底为 `(5.60, 4.15, 1.36)`，杯底为 `(6.24, 4.30, 1.36)`。桌面在身体之后、前臂和圆手之前绘制，能遮住腹部，又不会挡掉拿餐具的手。

吃饭的勺尖实际回到碗中食物表面，再送到侧脸的嘴。杯子也用同一份图形从桌面移动到手中：杯底相对掌心是 `(-.64, +.46)`，杯口是 `(-.64, -.48)` 个身体单位。拿起前画在桌上，拿起后才改由真手握点驱动；不能桌上画一只简化杯，手上突然换成另一只杯。旧预览动作自带的碗必须关闭，否则房间会同时出现桌上碗和悬空碗。

洗手台需要同时满足台面、龙头与短手的关系。两间独卫使用深度 `1.05`、高度 `.60` 的低台面；真实出水口为 `(4.72, .675, .852)`，接水点为 `(4.72, .675, .64)`，站位为 `(4.816, 1.675)`，朝向 `2.13`。此时接水点位于角色侧面 `(2.60, -3.90)`，不会落在额头上。近侧真手先接水，再收回胸前；身体略转向观众，让两只圆手搓洗的过程清楚可见，然后转回原来的水流冲一下。不要强迫两只短手同时够到同一个远处水点，也不能把水滴画在原有休息手周围就称为洗手。毛巾目前是房间设施，拿毛巾擦手仍待补做，不能把接水与搓手的原型描述成完整的卫生流程。

这些位置来自同一投影和同一短手求解器。通过调整家具和站位，让实际握点可达；不要反过来改肩根或伸长胳膊。触点测试会检查勺尖、杯口、杯底和两只手的实际屏幕坐标，而不只检查动画阶段的名字。

床头灯使用灯座上实际画出的触控点。手到达这个点时才切换灯光，停留一下，再收回。衣柜的 `wardrobeHandle` 则直接返回正在转动的柜门把手坐标；开门、查看和关门期间，真手始终跟着同一个把手。只允许打开短手能够覆盖的角度，不通过把门与手分开移动来掩盖不相连的问题。

### 自己安排生活，也尊重另一个房间

自主生活先在当前房间选择可做的完整活动，做完之后停留片刻。完成至少两项活动后，下一次安排有约两成机会考虑走到相邻的公共空间或自己的房间；同一个目的地至少间隔九十秒，当前活动也有防止连续重复的间隔。因此换房包含走到门口、开门、穿过门与从另一侧进入，不是定时换一张背景。

自主选择范围是芽芽卧室、芽芽独卫、客厅和餐厨。伙伴卧室及其独卫可以手动参观，但不会被芽芽自动占用；开启自主生活后，她会走回客厅。当前这是有冷却时间和归属约束的自主调度，还没有把饥饿、昼夜或疲劳数值作为跨房决策条件。

## 工作台分区

房间画面承担观察宠物和点击物品；右侧工作台承担控制和实验。全屋地图、当前房间可做的事、表情、独立动作、角色研究放进有限数量的页签，不再把所有实验面板依次铺在页面下方。

“房间生活”和“独立动作预览”必须明确区分。房间生活遵守家具、门和路径关系；独立预览用于比较表情和骨架，允许清空场景。预览开关不应同时启动两个自主宠物。旧版研究页面可以保留单独入口，但主页面只保持一个主要观看区域。

## 验收

- 六个房间全部可达，两个卫生间分别只连接自己的卧室。
- 总平面无重叠，连接点确实在两间房的公共边上；门有反向配对。
- 床头、书桌、衣柜和低柜靠墙；餐椅对应餐桌；床头灯落在床头柜上。
- 空调、窗、镜子、画、顶灯不产生地面障碍。
- 家具占地在房间内，门前落脚点和通道不被家具覆盖。
- 同一交互阶段检查实际画面，不能只凭坐标检查通过就认定自然。
- 暂停、后台暂停、手动接管和自主行为都遵守同一个房间状态，不制造道具副本。

运行 `node test-yaya-home.mjs` 验证数据、纯状态模型与真实手臂求解器：覆盖六个房间之间全部三十条有向旅行、每间房的可用活动、床头灯、衣柜把手、书和小熊的所属切换，以及拿着物品或睡着时提出跨房请求。测试在每个小时间步检查步行未进入家具范围、肩根固定、手掌不超出可达距离、物品不会在拿放交界跳动；还运行六百秒固定随机种子的自主生活，检查真实跨房、目的地冷却和伙伴空间的归属。它并不替代截图验收：坐姿是否舒服、桌面遮挡是否正确、柜门是否挡住真手，仍需看真实画面。
